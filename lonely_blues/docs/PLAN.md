### 읽어낸 공식
1. **제목 = 계절·날씨 + 구체적인 장소 + 인물(직업) + 용도 키워드.** "눈 오는 날 + 서점 + 직원 + 커피와 독서를 위한 음악" 형태가 100만 단위로 터졌다. 최근의 짧은 시적 제목("쉼", "버스 정류장에서")은 성과가 10~100분의 1 수준이다 → **우리는 잘된 공식을 따른다.**
2. **겨울·눈 테마가 최상위.** 1·2·10위가 눈 오는 서점이다 → 지금(10월)부터 준비하면 11~2월 겨울 성수기에 맞출 수 있다.
3. **비주얼:** 사람 없는 밤의 장소(서점·카페·정류장·한옥) 사진 1장, 따뜻한 조명과 필름 같은 색 보정, **위아래 검은 띠(2.35:1 시네마 비율)**, 가운데 작게 자간 넓은 세리프 로고("BLUE PLAYLIST"). 썸네일에 큰 글자가 없다 — 영상 화면이 곧 썸네일.
4. **설명란:** 2~3줄짜리 짧은 시 + 해시태그(#playlist #가사없는음악 #jazz) + 제작 크레딧. 트랙리스트·챕터 없음.
5. **음악:** Suno로 만든 연주곡. 즉 **품질 기준선은 Suno**다.

### 우리가 다르게 할 점
- **이미지 저작권:** 벤치마크는 Pinterest 이미지를 가져다 쓴다(출처 불명 → 저작권 신고 위험). 우리는 gpu-art로 **직접 생성**해 이 위험을 없앤다.
- **장면 일관성:** Qwen-Image-Edit로 "같은 서점·같은 직원"이 계절마다 이어지는 세계관을 만든다 — 1위 공식(서점 직원)을 시리즈로 키운다.
- **가벼운 움직임:** 정지 화면 대신 눈·김·불빛이 살짝 움직이는 루프 (Wan 2.2) — 시청 지속시간과 차별화.
- **트랙리스트·챕터 제공** 여부는 A/B로 시험 (벤치마크는 없음).

## 3. 음악 생성 방식

수익화 채널이므로 **상업적 이용 가능 라이선스**가 최우선 기준이다.

| 옵션 | 방식 | 상업 이용 | 장점 | 단점 |
|---|---|---|---|---|
| **A. 상용 음악 생성 서비스** (Suno — 벤치마크가 사용, ElevenLabs Music, Stable Audio API, Artlist 등) | 프롬프트 → 오디오 | 유료 플랜에서 대체로 허용 | 품질 높음 | 곡당 비용, 약관 변경 리스크, Suno는 공식 API가 없어 자동화가 어려움 |
| **B. 오픈 모델 로컬 실행** (ACE-Step, Stable Audio Open 등) | GPU에서 직접 생성 | 모델별 상이 — **반드시 확인** | 곡당 비용 0, 대량 생성 | GPU 필요, 품질 편차, 세팅 부담 |
| **C. 절차적 생성** (코드 진행 + MIDI → 사운드폰트/VST 렌더) | 규칙 기반 작곡 | 사운드폰트 라이선스만 확인 | 완전한 저작권 소유, 블루스 12마디 형식과 궁합 좋음 | 음악적 완성도 확보가 어려움 |

> ⚠️ Meta MusicGen 가중치는 CC-BY-NC(비상업)이므로 수익화 채널에는 사용 불가. 다른 모델도 도입 전 라이선스를 재확인한다.

**권장안:** 이미 있는 GPU 서버(`remote_coding/gpu-art`, §3-1)를 활용해 **B(ACE-Step on ComfyUI)를 주력**으로 한다. 벤치마크가 Suno를 쓰므로 **품질 기준선은 Suno**다. Phase 0에서 벤치마크 영상 속 곡과 ACE-Step 결과를 나란히 들어 보고, 모자라는 장르만 A로 보완한다. 서점 재즈·피아노처럼 잔잔한 연주곡은 오픈 모델로도 기준선에 닿을 가능성이 높고, 블루스 기타 솔로가 가장 어렵다. 채널 이름이 Lonely Blues인 만큼 **블루스 기타 품질이 Phase 0의 핵심 판정 항목**이다 — 기준에 못 미치면 블루스만 A로 만들거나, 블루스 색이 옅은 재즈 발라드 쪽으로 무게를 옮긴다. C는 블루스 실험용 사이드 트랙으로 둔다. 생성기는 `Generator` 인터페이스로 추상화해 백엔드를 교체 가능하게 만든다.

## 3-1. GPU 서버 — `remote_coding/gpu-art` 활용

### gpu-art가 이미 해 주는 것
- RunPod RTX PRO 4500 Blackwell **32GB**를 필요할 때만 켜는 서버 (시간당 약 0.75달러, 꺼 두면 0원)
- `gpu.py start/stop/status/ssh`로 켜고 끄고, SSH 터널 너머 **ComfyUI**(`127.0.0.1:8188`)로 작업을 보냄
- 모델은 `models.txt`에 sha256과 함께 고정하고, 켤 때마다 새로 받음 (저장 공간 없음)
- 30분 동안 쓰지 않으면 팟이 스스로 지워짐 (ComfyUI 대기열·GPU 사용률·SSH 셸 기준)
- 설정은 환경 변수가 `.env`보다 우선 (`RUNPOD_POD_NAME`, `RUNPOD_LOCAL_PORT`, `RUNPOD_DISK_GB` 등)

### 이 프로젝트에서 쓸 곳
ComfyUI 하나로 **음악·그림·영상 루프를 모두** 만든다. 32GB면 아래 모델을 한 팟에서 돌릴 수 있다.

| 용도 | 모델 (ComfyUI 기본 지원) | 라이선스 | 비고 |
|---|---|---|---|
| 음악 | **ACE-Step 1.5 XL** (4B DiT, turbo 8단계 / sft 50단계) + Qwen 0.6B·4B LM — **확정** | **MIT**, 상업 이용 허용 (허가 데이터·로열티 프리·합성 데이터로 학습) | 연주곡, 장르·BPM·키를 프롬프트로 지정. 3분 곡 1개에 약 30~50초 (RTX A6000, 첫 실측) |
| 배경·썸네일 그림 | **Qwen-Image** (텍스트→그림) + **Qwen-Image-Edit-2511** (이미 gpu-art에 있음) | Apache-2.0 | Edit 모델로 채널 마스코트·화풍을 영상마다 일정하게 유지 |
| 배경 루프 영상 | **Wan 2.2** (그림→영상, 5초) | Apache-2.0 | 비·김·레코드 회전 같은 작은 움직임 |

> **2026-10-13 적용 완료:** `gpu.py`에 `GPU_MODELS_FILE` 추가, 팟마다 터널 pid·로그 분리, `gpu-art/models-music.txt`(약 30GB) 추가. RTX PRO 4500 재고가 없을 때가 있으므로 음악 팟은 `RUNPOD_GPU_TYPES`에 4090·L40S·A6000 등 대체 GPU를 함께 넘긴다(음악 모델은 24GB면 충분). 첫 기동은 RTX A6000(시간당 0.59달러)에서 모델 받기까지 114초. 생성 도구는 `tools/ace_step.py`.

### gpu-art에 필요한 작은 변경
지금 gpu-art는 게임 그림 전용이라 모델 목록이 `models.txt` 한 파일로 고정되어 있다. 게임 그림 서버를 건드리지 않도록 **모델 묶음(프로필)만 고를 수 있게** 한다.

1. `gpu.py`가 `GPU_MODELS_FILE`(기본 `models.txt`)을 읽도록 한 줄 바꾼다.
2. `gpu-art/models-music.txt`를 추가한다 (ACE-Step + Qwen-Image + Wan 2.2, 각각 sha256 고정).
3. 이 프로젝트는 아래처럼 **다른 이름·다른 포트**로 켜서 게임 그림 팟과 동시에 떠 있어도 엉키지 않게 한다.

```powershell
$env:RUNPOD_POD_NAME = "music-gpu"; $env:RUNPOD_LOCAL_PORT = "8189"
$env:GPU_MODELS_FILE = "models-music.txt"; $env:RUNPOD_DISK_GB = "120"
python ..\remote_coding\gpu-art\runpod\gpu.py start
```

`gpu.py`는 저장소 최상위 `remote_coding/.env`에서 `RUNPOD_API_KEY`를 읽으므로, 이 프로젝트에는 RunPod 키를 따로 두지 않는다.

### 작업 방식: 몰아서 생성
켤 때마다 모델을 받느라 5~15분이 걸리므로 **한 번 켜서 일주일치를 몰아서** 만든다.

```
bc gpu up  →  트랙 N곡 + 배경 그림 + 루프 영상을 ComfyUI 대기열에 넣음
           →  /view 로 결과를 runs/ 아래로 받아 옴  →  bc gpu down
(이후 후처리·믹스·렌더·업로드는 노트북 CPU에서)
```

- ComfyUI 워크플로는 API 형식 JSON으로 이 저장소의 `workflows/`에 두고, 프롬프트·시드·길이만 바꿔 넣는다.
- 받아 온 파일마다 모델·판·시드·프롬프트를 `catalog.db`에 기록한다 (재현·라이선스 근거).
- 비용 감(추정, Phase 0에서 실측): 팟 준비 약 0.1달러 + 영상 3개 분량(약 90곡 + 그림·루프)을 1~2시간에 생성 → **주 1~2달러 수준**.

### 장면(테마) 프리셋 (예시)
벤치마크처럼 **장면이 먼저, 장르는 장면을 따른다.** 하나의 장면 파일이 음악·그림·제목·설명을 모두 결정한다.

```yaml
# config/scenes/snowy_bookstore_night.yaml
id: snowy_bookstore_night
season: winter
place: 눈 오는 골목의 작은 서점
persona: 문을 닫고 혼자 책을 정리하는 서점 직원
title_ko: "playlist 눈 오는 밤, 서점 직원의 고요한 시간 ⎸ 커피와 독서를 위한 재즈"
poem_ko: |
  눈 오는 밤
  아무도 오지 않는 서점에서
  우리는 천천히 책장을 넘긴다
music:
  genre: cafe_jazz            # config/genres/cafe_jazz.yaml 의 악기·BPM·이펙트를 씀
  prompt: "soft late-night jazz trio, brushed drums, warm upright bass, gentle piano, cozy bookstore, snow outside, 70 bpm, instrumental"
  tracks: 30
  length_hours: 2
image:
  prompt: "cinematic film photograph, small bookstore at night, warm lamp light through windows, snow on the street, nobody, 35mm, muted colors"
  series_ref: bookstore_v1   # 같은 서점이 계절마다 이어지도록 Qwen-Image-Edit 기준 그림
loop: snow_falling            # Wan 2.2 루프 종류 (없으면 정지 화면)
```

- **이펙트:** `pedalboard`로 장르별 체인 적용 (로파이: 로우패스·비트크러시·바이닐 노이즈 / 블루스: 테이프 새츄레이션 / 카페: 룸 리버브)
- **라우드니스:** `pyloudnorm`으로 트랙별 -14 LUFS 정규화, 트루피크 -1 dBTP
- **믹스:** 3~5초 크로스페이드, 키/BPM 흐름을 고려한 곡 순서 정렬
- **산출물:** `mix.wav`, `tracklist.json` (곡 제목 + 시작 시각 → 유튜브 챕터로 사용)

## 5. 영상 제작

벤치마크의 화면 문법(§0)을 따른다.

- **배경:** 사람 없는 밤의 장소를 **필름 사진 느낌**으로 1장 — gpu-art의 Qwen-Image로 생성하고, 시리즈 장면(같은 서점 등)은 Qwen-Image-Edit로 이어 그림 (§3-1)
- **색 보정:** 따뜻한 조명 + 낮은 채도 + 필름 그레인. 벤치마크는 포토샵으로 하지만 우리는 채널 고정 LUT를 ffmpeg(`lut3d`)로 적용해 모든 영상의 톤을 맞춤
- **프레임:** 위아래 검은 띠(2.35:1) + 가운데 작고 자간 넓은 세리프 채널 로고 ("LONELY BLUES")
- **모션:** 정지 화면 대신 아주 작은 움직임 (내리는 눈, 김, 깜박이는 불빛) — Wan 2.2로 5초 클립을 만들고 ffmpeg로 이음매 없이 반복. 벤치마크와의 차별점
- **오버레이:** 없음이 기본 (벤치마크도 글자 없음). 곡 제목 표시는 A/B 시험
- **렌더:** ffmpeg로 루프 영상 + 오디오 합성, 1080p/30fps, 저모션이라 낮은 비트레이트로 렌더 시간 단축
- **썸네일:** 영상 화면 그대로 (큰 글자 없음, 띠 + 로고만). 썸네일 글자 유무는 A/B 시험

## 6. 메타데이터 & 업로드

### 메타데이터 자동 생성
- Claude API로 장면 파일(§3)에서 제목·짧은 시·해시태그 초안을 만들고 사람이 다듬음
- **제목 공식:** `playlist` + 계절·날씨 + 장소 + 인물 + `⎸` + 용도 키워드 (예: 커피와 독서를 위한 음악, 가사없는 곡, 중간광고x)
- **설명란:** 2~3줄 시 + 해시태그(#playlist #가사없는음악 #재즈 등) + 제작 크레딧 (AI 사용 사실 포함)
- **언어:** 한국어가 기본 (벤치마크 시청자층). 영어·일본어 제목 번역은 Phase 4에서 시험
- 타임스탬프 챕터는 넣는 버전/안 넣는 버전을 A/B 시험 (벤치마크는 넣지 않음)

### YouTube Data API v3
- OAuth 2.0 (데스크톱 앱 플로우), 리프레시 토큰 로컬 저장
- `videos.insert` 업로드 → `thumbnails.set` → 플레이리스트 추가
- `status.publishAt`으로 예약 공개 (최적 시간대에 맞춰 배치)
- 합성 콘텐츠 여부 공개 설정 (`containsSyntheticMedia`) 적용
- **할당량:** 기본 10,000 units/일, 업로드 1건 ≈ 1,600 units → 하루 약 6건이 상한
- **주의:** 미검증 API 프로젝트로 올린 영상은 비공개로 잠김 → Google API 감사(audit) 신청 필요, 승인 전까지는 수동 업로드 병행

## 8. 기술 스택 & 구조

- **sft 탈락:** 끌리지 않는다. 시간도 turbo(약 35초)의 두 배다. 앞으로는 **turbo만** 쓴다.
- **A와 B의 성향:** A는 주제에 충실하게 시도하지만 성공률이 낮고, B는 안전하게 가는 느낌이다.
  - 다만 A와 B는 같은 설정에 시드만 다르다. 이 차이는 시드 운이지 모델의 체계적 성향이 아닐 가능성이 크다.
- **합격률:** 장면 기준 6/10, 곡 기준 6/20(30%)
  - 곡당 합격률이 30%라면 장면마다 후보를 4개 만들면 하나 이상 합격할 확률이 약 76%, 6개면 약 88%다.

- **채널 대표 장르인 블루스가 1/3로 가장 약하다.**
  - 프롬프트를 고친다: 악기를 좁히고 bpm과 shuffle을 명시한다.
  - Suno 기준선과 나란히 다시 들어 본다.
- **lofi_study 다시 쓰기:** "lo-fi hip hop"을 더 직접적으로 쓴다(예: sidechained, low-pass filtered, detuned keys, 70-85 BPM).
- **기술 문제**
  - 모든 곡 끝에 6~9초 무음이 있다. 모델이 3분보다 일찍 끝낸다. 후처리에서 잘라내고 크로스페이드로 잇는다.

**처방** (비용이 적은 순서)

1. **생성 단계:** `tools/ace_step.py` 에서 SaveAudio 직전에 `AudioAdjustVolume`(-4dB) 노드를 넣는다. 모델 출력이 1.0을 넘는데 그대로 저장돼 잘리는 것을 막는다. — **다음 할 일**
2. **후처리 마스터링(로컬 ffmpeg):** `adeclip` 으로 잘린 파형 복원, 먹먹한 곡에만 high-shelf EQ, 좌우 폭 보정, 가벼운 압축, -14 LUFS. §4 후처리에 그대로 쓴다. 이번 20곡 중 3~4곡을 원본·처리본으로 나란히 비교한다.
3. **sft 다듬기 패스:** 고른 turbo 곡을 출발점으로 sft를 denoise 0.2~0.3으로 한 번 더 돌린다. 구성은 두고 질감만 다시 그린다.
4. **AI 업스케일(AudioSR 등):** 고음을 새로 채운다. 팟에 설치해야 하고 라이선스도 확인해야 한다.
